## 使用场景
触发场景：
- 解释 / 梳理 Vibe Coding 项目开发流程（阶段、交付物、最佳实践）
- 拆解里程碑 / Sprint / 周计划（需用户提供团队规模与时间预算）
- 生成 RESEARCH.md / PRD.md / TECH_DESIGN.md / AGENTS.md 文档模板
- 识别反模式（直接写代码、需求不清、不用版本控制等）并给出改进意见
- 提供 Prompt 优化建议、多模协作技巧、AI 失控应对方案

# Vibe Coding 项目开发流程 · 完整知识库
- 缺少全局文档 → AI 不知道项目整体设计，最终推倒重来

清晰流程的价值：

1. 明确项目目标和需求
2. 让 AI 理解你的意图
3. 避免项目失控
4. 提高开发效率
5. 做出真正有用的产品

---

## 完整的 5 步工作流

步骤一  需求研究（Research）
步骤二  产品需求文档（PRD）
步骤三  技术设计文档（Tech Design）
步骤四  AI 代理指令（AGENTS.md）
步骤五  实现和迭代（Build）

---

## 步骤一：需求研究（Research）

**目标**：搞清楚要做什么、为什么做、有无现成参考。花 30 分钟调研，可避免大量弯路。

### 三步做法

1. **明确你的目标**
   - 我想解决什么问题？这个问题值得解决吗？
   - 给自己用还是给别人用？核心功能是什么？

2. **调研类似产品**
   - 搜索相关应用 / 网站，看开源项目
   - 直接问 AI："有哪些好用的 xxx 应用？它们有什么特点？"
   - 记录优点、缺点、可借鉴点

3. **记录发现（RESEARCH.md）**

### RESEARCH.md 模板

```markdown
# [项目名] 需求研究

## 目标
[一句话描述：做什么、给谁用、解决什么问题]

## 调研发现
- [竞品1]：优点 xxx，缺点 xxx
- [竞品2]：优点 xxx，缺点 xxx
- 市场空白 / 差异化机会：

## 核心需求
1. [需求1]
2. [需求2]
3. [需求3]
```

## 步骤二：产品需求文档（PRD）

**目标**：把调研结论整理为正式文档，明确做哪些功能、不做哪些功能。  
这是整个流程最重要的一步——好的 PRD 让 AI 准确理解意图，生成高质量代码。

### 建议流程

1. 先写 2～3 句话的简短需求描述
2. 把它发给 AI 大模型（Gemini / DeepSeek 等），让它扩展为完整 PRD
3. 根据自己的需求修改和完善

#### 让 AI 扩展 PRD 的 Prompt 模板

```
请帮我把这个需求扩展成完整的产品需求文档（PRD），要包含：
1. 产品概述和目标用户
2. 详细的功能列表
3. 功能优先级（MVP 和后续版本）
4. 界面设计要求
5. 技术栈建议
6. 非功能性需求（性能、安全等）
```

### PRD.md 模板

```markdown
# [项目名] PRD

## 产品概述
[一句话描述产品是什么]

## 目标用户
[谁会用这个产品]

## 核心功能

### 必须做（MVP）
1. [功能1]
   - 子功能描述
2. [功能2]

### 后续可以做
- [扩展功能1]
- [扩展功能2]

## 界面设计
- [页面1]：[简单描述]
- [页面2]：[简单描述]

## 技术栈建议
[前端 / 后端 / 数据库 / 部署]

## 代码风格和架构模式
[规范说明]

## 非功能性需求
- 性能：
- 安全：
- 兼容性：
```

## 步骤三：技术设计文档（TECH_DESIGN.md）

**目标**：确定用什么技术来实现，以及大致的技术架构。
不熟悉技术选型时，直接问 AI："我要做 xxx 应用，应该用什么技术栈？"

### TECH_DESIGN.md 模板

```markdown
# [项目名] 技术设计

## 技术栈
- 前端：[框架 + 语言 + 构建工具]
- 样式：[CSS 方案]
- 数据存储：[数据库 / LocalStorage / 云存储]
- 部署：[平台]

## 项目结构

src/
  components/     # 组件
  pages/          # 页面
  hooks/          # 自定义 Hooks
  utils/          # 工具函数
  types/          # 类型定义

## 数据模型

### [实体名]
- id: string
- [字段1]: [类型]   // [说明]
- [字段2]: [类型]

## 关键技术点
1. [技术难点1]：[处理方式]
2. [技术难点2]：[处理方式]
```

## 步骤四：AI 代理指令（AGENTS.md）

**目标**：创建一份专门给 AI 看的「工作手册」，告诉 AI 在这个项目中应遵循什么规则。

- 推荐文件名：`AGENTS.md`（新兴社区标准，8 万+ 开源项目采用）
- 也可以用：`AI_RULES.md`、`INSTRUCTIONS.md`、`copilot-instructions.md`
- 主流 AI 工具（Cursor、Windsurf、Claude Code、Gemini CLI、GitHub Copilot）均支持自动读取

### AGENTS.md 模板

```markdown
# [项目名] AI 开发指令

## 项目概述
[简短描述项目是什么、用什么技术做]

## 开发规范
- [规范1]
- [规范2]

## 代码风格
- 命名：组件用 PascalCase，函数用 camelCase，常量用 UPPER_SNAKE_CASE
- 工具：ESLint + Prettier

## 测试要求
- 每个功能完成后手动测试
- 确保数据正确存储和读取
- 测试各种边界情况

## 开发环境（按需填写）
- 操作系统：[Windows / macOS / Linux]
- 终端：[PowerShell / zsh / bash]
- 请使用与上述环境兼容的命令

## 注意事项
- 保持代码简洁，避免过度设计
- 优先实现核心功能
- 确保移动端适配
```

> Windows 用户必须在此文件中声明操作系统，AI 生成的命令默认面向 Linux/Mac。

## 步骤五：实现和迭代（Build）

**原则**：小步迭代，而非一口气写完。

### 3 步走策略

#### 1. 生成基础框架

```
请根据 PRD.md、TECH_DESIGN.md 和 AGENTS.md 的要求，
初始化项目并创建基本的项目结构，包括：
1. 安装必要的依赖
2. 创建目录结构
3. 配置开发环境
4. 创建基础的路由和页面框架
确保项目能够正常启动。
```

> 有编程基础时：优先使用脚手架（create-react-app、create-vite 等）或项目模板。

#### 2. 逐步实现核心功能

先跑通核心业务流程，再考虑完美。每次只实现一个功能：

```
我要实现[功能名]，请根据 PRD.md 和 TECH_DESIGN.md 中的要求，
创建 [组件/文件名]，包含[具体内容]。
```

每完成一个功能 → 测试（功能是否正常、有无 Bug、界面是否符合预期）→ 通过后再进行下一个。

#### 3. 优化实现细节

在保证不影响功能的前提下，优化性能、改进用户体验、美化界面。
MVP 完成后即可上线，之后根据反馈迭代。

## 避免 AI 失控的 6 个关键技巧

### 1. 项目模块化

把大项目拆成独立模块，针对单个模块提供上下文，避免 AI 因信息量过大而「遗忘」。

> 开发电商系统时，实现「添加商品」只需提供商品表字段和业务逻辑，无需把支付、会员等无关模块一并提供。

### 2. 限定修改范围

```
仅修改 components/AddTransaction.tsx 文件：
1. 添加表单验证功能
2. 保持现有的样式和布局
3. 不要改动其他文件
```

### 3. 抽象和复用

```
请帮我抽象这个页面为可复用的组件，
让其他页面可以通过传入不同的参数来使用。
```

### 4. 版本控制（Git）

```bash
# 每完成一个功能后提交
git add .
git commit -m "实现[功能名]"
```

在 AI 生成新代码后，人工 diff 对比变动文件；出了问题随时回退。

### 5. 人工控制

当 AI 陷入循环或反复出现同样错误时：

- 清空对话重新开始（先保存重要信息）
- 换角度提问，逐步排查：
  ```
  请检查登录流程的每一步：
  1. 前端是否正确发送了请求？
  2. 后端是否收到了请求？
  3. 数据库查询是否正确？
  4. 返回的数据格式是否正确？
  请逐步排查并告诉我哪一步出了问题。
  ```
- 手动修改关键代码给 AI 正确方向
- 提供更多上下文（代码 + 错误信息 + 网络请求日志）

### 6. 多模协作

不同 AI 擅长不同任务，可以互补：

1. 把代码和错误复制给 Claude / Gemini
2. 让它分析问题并给出修改建议
3. 再把建议告诉原来的 AI 执行修改

## 实战技巧：让 AI 生成的代码更准确

### 1. 优化 Prompt 的三要素

- **明确角色**："你是一个经验丰富的前端开发工程师，擅长使用 React + TypeScript 开发现代化 Web 应用。"
- **提供具体细节**：列出所有要求（样式方案、状态管理、每种状态变体）
- **拆解复杂任务**：分步骤，一次只完成一步

**对比示例（组件）**：

```
坏 Prompt：帮我做一个按钮

好 Prompt：
创建一个主要操作按钮组件：
- 使用 Tailwind CSS
- 支持 primary、secondary、danger 三种样式
- 支持 loading 状态（显示加载动画）
- 支持 disabled 状态
- 点击时有反馈动画
```

**对比示例（复杂功能）**：

```
坏 Prompt：实现用户管理功能

好 Prompt：
第一步：创建用户数据模型和类型定义
第二步：实现用户注册接口
第三步：实现用户登录接口
第四步：实现用户信息查询接口
现在请先完成第一步。
```

### 2. 注意操作系统差异

AI 更熟悉 Linux / Mac 终端命令，Windows 用户须在 AGENTS.md 中声明：

```markdown
## 开发环境
- 操作系统：Windows
- 终端：PowerShell
- 请使用 Windows 兼容的命令
```

### 3. 提供参考设计

```
参考这个登录页面的设计风格：[截图或链接]，
创建一个注册页面，保持风格一致。
```

### 4. 让 AI 帮你优化 Prompt

```
我想让 AI 帮我实现用户登录功能。
我现在的 Prompt 是："实现登录功能"
请帮我优化这个 Prompt，让它更详细、更准确，
让 AI 能生成高质量的代码。
```

### 5. 利用 AI 做代码审查

```
请审查我的登录功能代码，检查：
1. 是否有安全问题（如密码明文传输）
2. 是否有性能问题
3. 代码是否符合最佳实践
4. 是否有潜在的 Bug
5. 用户体验是否可以改进
请给出具体的改进建议。
```

> 核心功能建议让多个 AI 模型交叉审查，互相验证。

## 反面教材（小阿巴的失败案例）

1. 直接输入"帮我做一个待办事项应用"（无 PRD、无规划）
2. 生成结果不满意 → "加上分类功能"
3. 分类破坏了布局 → "修复布局问题"
4. 布局修好又引入新 Bug → 来回循环 → 代码一团糟 → 放弃项目

**根本原因**：没有明确需求 + 没有整体规划 + 没有文档记录。

## 关键原则总结

| 原则 | 说明 |
|------|------|
| Planning is Everything | 规划比代码更重要，这是 Vibe Coding 第一心法 |
| 文档是 AI 的指南针 | PRD + TECH_DESIGN + AGENTS.md 三件套缺一不可 |
| 小步迭代不失控 | 每次只实现一个功能，完成后测试再推进 |
| 模块化是大项目的关键 | 功能隔离，减轻 AI 上下文负担 |
| 版本控制是后悔药 | 每个功能完成后 git commit，出问题随时回退 |
