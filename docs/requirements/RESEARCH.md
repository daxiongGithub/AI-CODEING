# PocketBook (口袋账本) 需求研究

> 基于 Vibe Coding 流程 Step 1

## 1. 竞品调研

### 主流竞品分析
| 产品 | 优点 | 缺点 | 参考价值 |
| :--- | :--- | :--- | :--- |
| **随手记** | 功能极其全面，社区活跃，报表丰富 | 广告多，臃肿，启动慢，隐私顾虑 | 分类图标体系，记账流程 |
| **MoneyMoney** (Mac/iOS) | 极简设计，本地存储，体验极佳 | 主要是手动记账，自动化程度低，即使有导入也较为繁琐 | 极简风格，交互体验 |
| **Wallet** (BudgetBakers) | 银行同步功能强大，全平台 | 订阅制价格高，国内银行支持一般，数据云端存储 | 借贷管理，预算管理 |
| **Toshl** | 趣味性强，交互独特（怪物形象） | 交互过于非主流，效率有时受影响 | 趣味数据展示 |

### 我们的差异化机会
1.  **隐私安全 (Privacy First)**: 很多用户反感云端同步带来的隐私泄露风险。**PocketBook 主打完全本地存储**，数据掌握在用户自己手中。
2.  **极速记账 (Speed)**: 随手记等大而全的应用启动慢。我们追求**秒开秒记**。
3.  **截图记账 (AI/OCR)**: 手动记账难以坚持。通过**OCR 截图回填**降低记账阻力，这是核心杀手锏。

## 2. 核心用户画像

-   **注重隐私的个人理财者**: 不希望财务数据上传到第三方服务器。
-   **懒人记账用户**: 经常因为忘记或者觉得麻烦而中断记账，需要 OCR 辅助。
-   **极简主义者**: 讨厌广告和繁杂的理财社区推广，只想要纯粹的记账工具。

## 3. 功能 Backlog 与 迭代规划

### 核心价值验证 (MVP) - 预计 8-12 周
> 目标：验证“本地存储 + OCR 辅助”的记账体验是否足够顺滑。

1.  **手动记账**: 极致流畅的记账体验（<3秒完成）。
2.  **OCR 截图记账**: 识别截图 -> 自动填单 -> 人工确认。准确率 > 95%。
3.  **本地数据管理**: SQLite 存储，支持 CSV 导出。
4.  **基础统计**: 日/月 维度的收支统计。

### 后续迭代 (V2+)
1.  **借贷管理**: 独立的借入/借出台账。
2.  **高级统计**: 年/周 维度，趋势分析。
3.  **资产管理**: 账户余额管理（微信、支付宝、银行卡）。
4.  **预算管理**: 设置月度预算并提醒。
5.  **数据备份**: JSON 全量备份与恢复。

## 4. 结论
PocketBook 应避开与“随手记”等巨头在“全功能”赛道的正面竞争，专注于**“本地+智能”**的细分领域，用 OCR 解决“懒”的问题，用本地存储解决“不安全”的顾虑。
